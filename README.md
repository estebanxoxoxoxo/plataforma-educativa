# Innerith UI

UI de Innerith (React + TypeScript + Vite), portada 1:1 del prototipo `../index.html`.

```bash
npm install
npx tsx server/scripts/dump-smarty-defaults.ts "<ruta a smarty-poc>"   # una vez: valores de fábrica → server/data/defaults.json (sin él la API no levanta)
npm run import:smarty -- "<ruta al smarty-all-*.json>"              # una vez: claves + listas + catálogo de Smarty (pide el PIN sin mostrarlo)
npm run dev         # TODO de una: web (Vite) + API (8787) + route-lab (5203)
npm run dev:web     # solo la web
npm run dev:server  # solo lo de atrás: API + route-lab
```

**La API escucha SOLO en esta máquina** (`127.0.0.1:8787`; FS-BASE-B, 29-oct): no hay login —la cabecera `X-Innerith-User` es
la única "sesión"— y antes, abierta en todas las interfaces, cualquiera en la misma red podía leer los avisos de crisis o apagar
protecciones como el adulto. El navegador llega igual: la web (Vite) la llama por su proxy desde esta misma máquina. **Probar
desde un teléfono** (la prueba con iPhone real de T6), en la misma Wi-Fi:
- la web: `npx vite --host` (o `npm run dev:web -- --host`) y abrir en el teléfono `http://<IP de esta máquina>:5173`; las
  llamadas a `/api` siguen yendo por el proxy de Vite, así que la API NO necesita abrirse;
- solo si un cliente le pega a la API directo desde otro equipo: `INNERITH_LAN=1` al arrancarla (escucha en todas las
  interfaces y lo avisa en el log). Cerrala al terminar.
- en macOS, el firewall tiene que dejar entrar a `node` (en esta máquina, el 29-oct, estaba en «bloquear todas las conexiones
  entrantes»: con eso el teléfono recibe "connection reset" aunque el puerto esté abierto).

`npm test` corre sin `server/data/` (clon limpio o CI): `config.ts`, solo bajo vitest y solo si faltan, lee los fixtures de
`server/src/__tests__/fixtures/` (una config sintética y los valores de fábrica).

`import:smarty` descifra el respaldo COMPLETO de Smarty (`smarty-all-*.json`, el botón «Todo» del respaldo) con el PIN del padre y escribe `server/.env` (claves de API), `server/data/config.json` (sitios aprobados, temas, reglas de dominio, palabras bloqueadas, prompts editados) y `server/data/catalog.json` (los videos aprobados). Las tres rutas están en `.gitignore` y quedan con permisos 0600 (solo tu usuario); lo que había antes queda en `<archivo>.pre-import`.

**El PIN nunca va en la línea de comandos** (FS-BASE-A, 29-oct): el script lo pide en la terminal sin mostrarlo; sin terminal interactiva, `SMARTY_PIN_FILE=<archivo que solo tiene el PIN> npm run import:smarty -- "<ruta>"` (lo lee y BORRA el archivo). La forma vieja, `SMARTY_PIN=… npm run …`, ahora se rechaza: dejaba el PIN en el historial del shell y a la vista de `ps` mientras corría. Si ya lo corriste así alguna vez, borrá esa línea de `~/.zsh_history` (y de `~/.zsh_sessions/`) y cambiá el PIN en Smarty.
Antes de escribir NADA el importador valida, y si algo no pasa termina con un error claro sin tocar ningún archivo: formato `smarty-backup` y ámbito `all` (un `smarty-setup/-catalogo/-sesion` vaciaba en silencio el catálogo, las claves o los filtros de fábrica), que no se vacíe lo que hoy tiene datos (catálogo, palabras, temas, sitios, claves; `--force` para aceptarlo), que cada clave sea un token sin saltos de línea ni caracteres de control (una clave con `\n` plantaba `NODE_OPTIONS` en `server/.env` = código ajeno en cada arranque) y que el respaldo venga cifrado (uno en claro solo con `--allow-plain`).
**Después de importar, borrá el respaldo** (y vaciá la Papelera) o guardalo en un volumen cifrado: la clave es el sha256 de un PIN de 6 dígitos, que se adivina en segundos, así que el archivo equivale a texto plano (claves, ficha y chats del chico). No lo mandes por mail, chat ni Drive.

Abrí con `?stage` (por ejemplo `http://localhost:5173/?stage`) para verla en el lienzo de 1280×720 escalado, igual que el prototipo, y comparar.

## Estructura

| Carpeta | Qué hay |
|---|---|
| `src/api/types.ts` | Contratos de datos (lo que el backend tiene que devolver) |
| `src/api/index.ts` | Cliente de API contra el backend (`server/`): todo real o fake DE SERVER. Pone la cabecera `X-Innerith-User` (usuario activo) en cada llamada y loguea en la consola (`[api] → GET …`) |
| `src/sections/<sección>/` | Una carpeta por punto del menú: `home`, `discover`, `learn` (Aprender = Learn: aprender + practicar + Active Recall colapsados), `create`, `leagues`… (`friends` ya no es punto del menú: es el dock de Mensajes, presente en toda la app) |
| `src/learn/` | El MOTOR de actividades del porte Smarty (W2: núcleo, los 5 Tipos con sus tableros, registry, definiciones, audio/visual) + `recall.ts` (la urgencia del Active Recall, W4). Puro: sin API |
| `…/containers/` | Pantallas y paneles que piden datos a `api` y arman la vista |
| `…/cards/` | Ítems de listas y grillas (resultado, curso, amigo, liga, opción de respuesta…) |
| `…/components/` | Piezas visuales puras (reciben props; no llaman a la API) |
| `…/lib/` | Helpers sin UI de la sección (layout del camino, formato, etc.) |
| `…/<sección>.css` | Estilos de la sección |
| `src/shared/` | Lo común a todas: barra lateral, íconos, avatar, solapas, esqueleto |
| `src/styles/` | CSS global (base y layout) |

Una sección puede usar piezas de otra: Learn lee los artículos con el lector de `discover` (`WikiArticle`) y toma las categorías de `create`.

Todas las vistas comparten UNA columna central (1040px máx, centrada), definida por `.view` en
`styles/shell.css` con los tokens `--content-w`/`--view-px`; las secciones no definen ancho de página (excepciones más
angostas, centradas en el mismo eje: reproductor 760, lector 900 y el hilo del Feed 780). Los overlays de Learn (actividad,
lectura y video de una posta) van a pantalla completa en un portal sobre `<body>`.

## Diferencias con el prototipo

- Corregidos los estilos que se pisaban: barra del reproductor (`.pbar` → `.vbar`), fila "Rango temporal" del cuadro de Wikipedia (`.sub` → `.wk-sub`), perfil lateral (`.kid` → `.profile`) y clase de imágenes (`.ph` → `.ph-img`).
- La miniatura compartida en el chat muestra la foto (en el prototipo, un SVG la tapaba).
- El temporizador muestra `1:00` en vez de `0:60`.
- Agregados: estados de respuesta incorrecta y de tiempo agotado, y mensaje de búsqueda sin resultados.
